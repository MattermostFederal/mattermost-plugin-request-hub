Approving requests

Cards land in plugin-managed private channels under the configured approval team (channel / Channel Admin → mattermost-channel-requests; team creation / Team Admin / team member / guest → mattermost-team-requests; bots → mattermost-bot-requests; webhooks → mattermost-webhook-requests).

Channel and team cards are single-step (System Admins; Team Admins when enabled for channel types). Team Admin cards can also be approved by the Team Admins of the requested team, and go to that team's mattermost-channel-requests channel when it has one. With Team Admins can approve team creation on, Team Admins of the approval team can approve team creation cards. Only a System Admin can approve a request they made themselves. Bot and webhook cards are two-step (security + system).

Bot & webhook two-step approval

Each bot/webhook card needs two distinct approvers on the same card:

  • Security first — security pool (attribute or group). System Admins do not auto-qualify once a security pool is set. Dual-role (both pools / security + System Admin) fills security only.
  • System second — a different System Admin or system-pool member. System-only cannot click before security has signed off.

Configure pools in System Console → Plugins → Mattermost Request Hub → Bot/webhook two-step approver mode.

Mode: User Attributes (ABAC / CPA)

Default. Uses Mattermost User Attributes (custom profile attributes).

  1. System Console → User Management → Attributes — create attributes (admin-managed or LDAP/SAML-synced).
  2. Set Security approver attribute name and System approver attribute name to match your schema (defaults security_approver / system_approver — rename freely).
  3. Mark the right users with those attributes.

System Admins always qualify for the system step. They do not bypass a configured security attribute — create the attribute and mark security reviewers, or clear the security attribute name if you intentionally want the setup soft-fallback.

Mode: User Groups

Use when ABAC is not available but you have Mattermost groups (custom or synced).

  1. Create groups (System Console → User Management → Groups). Defaults expect security-approvers and system-approvers — create those, or rename the plugin fields to match yours.
  2. Set mode to User Groups.
  3. Confirm Security approver user group and System approver user group match the group name/handle (not display name). Both fields are editable in System Console.

Security-group members fill security first. System-group members or System Admins fill system second — always two different people. Someone who is in the security group and a System Admin still only fills security on their click; another person must complete system. If the security group name is blank, System Admins may cover the security step (setup soft-fallback), but a second distinct approver is still required for system.

Mode: System Admins only (no ABAC)

Intentional backup when neither attributes nor groups are set up. Only System Admins can approve; one System Admin can complete both steps on a single click. Prefer attributes or groups in production when you need true two-party separation.
