Docs / Webhooks

Request a webhook (standalone)

Use this when you don't need a new bot. Two-step approval. See Approving.

How to open

  • Native: Main Menu → Integrations → Incoming or Outgoing Webhooks (non–System Admins)
  • Dropdown: channel More actions → Request Incoming/Outgoing Webhook
  • Hub: right App Bar plug → Requests → the webhook tile
  • Slash: /mattermost-request-hub webhook-incoming or webhook-outgoing opens the form; add arguments to skip it (see Slash commands)
  • Agent: when Offer tools to Agents is on, ask an AI agent to file it for you (see AI agents)

Forms & approve

Outgoing webhooks need a public channel: Mattermost runs them only on public channels.

Before either approval step, Approve checks that the requester is still active, the channel still exists and isn't archived, the requester is still in it (System Admins excepted), and an outgoing webhook's channel is still public. If not, the approver gets a private message and the request stays as it was, so it can be denied (see Requests that can't be approved as they stand).

Limits

A System Admin sets how many webhook requests you can have waiting for review at once (Pending requests per user; each request type is counted separately). At the limit, you'll see you have N pending requests waiting for review; you can submit more once some are approved, denied or expire.

Asking again for a webhook of the same type with the same name in the same channel shows you already have a pending incoming webhook request with this name in this channel (or outgoing). Requests that aren't reviewed within Request expiry (days) of being submitted expire, even if one approval step is done, and your ticket DM says so.
