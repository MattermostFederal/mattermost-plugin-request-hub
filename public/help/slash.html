Slash commands

Same requests as the hub and native menus, from the message box. Replies are only visible to you.

CommandWhat it does
/mattermost-request-hub docsLinks to this documentation (overview).
/mattermost-request-hub helpLists every subcommand and its arguments, with a link to this documentation.
/mattermost-request-hub channelOpens the Request a Channel form. /mattermost-request-hub on its own does the same.
/mattermost-request-hub channel <prefix> <Channel name> [options]Requests a channel in the current team without the form. See below.
/mattermost-request-hub channel-adminOpens the Request Channel Admin form.
/mattermost-request-hub channel-admin @user [@user ...]Asks for those channel members to be made Channel Admins of the channel you run it in. See below.
/mattermost-request-hub prefixesLists the channel prefixes you can use, with each one's description and suffix rule.
/mattermost-request-hub teamOpens the Request a Team form.
/mattermost-request-hub team <Team name> [options]Requests a new team without the form. See below.
/mattermost-request-hub team-adminOpens the Request Team Admin form.
/mattermost-request-hub team-admin @user [@user ...]Asks for those team members to be made Team Admins of the current team.
/mattermost-request-hub team-memberOpens the Request Team Members form.
/mattermost-request-hub team-member @user [@user ...] [--reason <text>]Asks for those users or bots to be added to the current team.
/mattermost-request-hub team-guestOpens the Request Guest Invite form.
/mattermost-request-hub team-guest <email> --channels ~channel [~channel ...] [--reason <text>]Asks for a guest invite to those channels of the current team.
/mattermost-request-hub botOpens the Request a Bot form.
/mattermost-request-hub bot <username> <Display name> [options]Requests a bot account without the form.
/mattermost-request-hub webhook-incomingOpens the incoming webhook form.
/mattermost-request-hub webhook-incoming ~channel <Display name> [--description <text>]Requests an incoming webhook that posts to that channel.
/mattermost-request-hub webhook-outgoingOpens the outgoing webhook form.
/mattermost-request-hub webhook-outgoing ~channel <Display name> --callback <url> [--description <text>]Requests an outgoing webhook for that channel.

Each request subcommand opens its form when you give it no arguments. With arguments, it files the request directly, with the same checks, approvers and confirmation as the form. If something is wrong, the reply says what, and nothing is submitted. A request type a System Admin has turned off in the System Console replies that it is disabled, and help leaves it out. Requests made with a slash command always go to the approvers, even when a System Admin runs it. An unknown subcommand replies with the list above.

Requesting a channel without the form

The prefix comes first, typed exactly as /mattermost-request-hub prefixes lists it (for example team-). Then comes the channel name, which can be several words, then any options in any order. Each option takes the words up to the next --.

OptionWhat it does
--suffix <suffix>The URL part after the prefix, as one word. Leave it out to generate it from the channel name.
--purpose <text>A short description of the channel.
--privateMakes the channel private. Without it the channel is public.
--members @user ...Users who become regular members on approval.
--admins @user ...Users who become Channel Admins on approval.
--category <name>Sidebar category to place the channel in on approval. It can be several words; a missing category is created.

For example:

/mattermost-request-hub channel team- Marketing Team --purpose Campaign planning --members @alice @bob --admins @carol
/mattermost-request-hub channel ops- SRE On-call --suffix sre-oncall --private --category Operations

The request goes through the same checks and approval as the form, and you get the same confirmation. If something is wrong, such as an unknown prefix, an unknown @user or a suffix that breaks the prefix's rule, the reply says what, and nothing is submitted.

Requesting Channel Admin without the form

Run /mattermost-request-hub channel-admin @user [@user ...] in the channel itself. You must be a member of it (System Admins excepted), and everyone you name must already be a member too; the request never adds anyone to the channel. The approvers are the same as for the form. The command isn't hidden from people who already admin the channel, but they can manage it directly instead.

Other requests without the form

Team Admin, team member and guest requests are for the team you run the command in. Name channels as ~channel, using the name from the channel's URL, and users as @user.

CommandArguments and options
teamThe team name, which can be several words, then --name <url name> (leave it out to generate it from the team name), --description <text>, --invite-only (without it the team is open) and --team-admin (make you a Team Admin of the new team).
team-adminOne or more @user. You must be a member of the team.
team-memberOne or more @user, then --reason <text> if you want to give one.
team-guestThe guest's email, then --channels with one or more ~channel, then --reason <text> if you want to give one.
botThe bot's username as one word, then its display name, which can be several words, then --description <text> and --owner @user. Access tokens and webhooks for the bot are only in the form.
webhook-incomingThe ~channel it posts to, then its display name, then --description <text>.
webhook-outgoingThe ~channel it listens in, then its display name, then --callback <url> and --description <text>.

For example:

/mattermost-request-hub team Field Support --description Support for field teams --invite-only
/mattermost-request-hub team-member @alice,@bob --reason Joining the ops rotation
/mattermost-request-hub team-guest guest@example.com --channels ~town-square ~vendor-chat
/mattermost-request-hub bot build-bot Build Bot --description Posts build results --owner @carol
/mattermost-request-hub webhook-outgoing ~deploys Deploy Hook --callback https://ci.example.com/hook

Typing arguments

  • Each option takes the words up to the next word that starts with --, so names, purposes and descriptions can be several words.
  • Put quotes around text that should stay as typed, for example --purpose "--draft-- plans". Inside quotes, a word that starts with -- is just text. The quote marks themselves are not saved. Curly quotes work too.
  • Separate users or channels with spaces or commas: @alice @bob, @alice,@bob and @alice, @bob mean the same.
  • A long dash that your device typed in place of -- works like --.
  • A ~channel must be a public channel of the team, or a private one you are in.

Markdown sources for contributors live in the plugin repo under docs/ (including admin-guide.md for System Console setup).
